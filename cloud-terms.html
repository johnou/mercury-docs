Scripts and administrator responsibility

Your organization controls its scripts, configuration, issue selection, and enabled automations. Jira administrators must review source, permissions, proposed writes, pinned revisions, execution limits, and project filters before enabling live execution.

Simulation and dry run help with review but do not prove that a later live Jira request will succeed. Completed Jira writes cannot be rolled back by Mercury. Automatic execution is not exactly once, and Mercury does not automatically replay a failed run.

Execution controls

Mercury applies source, runtime, Jira-call, automation-count, and installation usage limits. The server admits no more than 100 runs per UTC hour or 10,000 per UTC month for one installation, and an administrator can lower those limits. These counters are operational controls rather than a spending or billing meter. An administrator can pause new execution. Pause does not cancel a run that has already started. Mercury may reject or suspend execution when a license is inactive, a limit is reached, or continued execution could threaten the app or Atlassian services.
